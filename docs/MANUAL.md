## 1. 이 프로그램으로 할 수 있는 일

Yaskawa · Kawasaki · Hyundai · ABB · KUKA · Doosan 로봇 컨트롤러를 **하나의 가상 컨트롤러**로 흉내 냅니다.

| 하고 싶은 일 | 이 프로그램에서 |
|---|---|
| 로봇이 입고되기 전에 PLC 인터록·핸드셰이크 로직을 짜고 시험 | Modbus TCP / OPC UA 서버, DI/DO 512점, 상태·명령 레지스터 |
| 제조사 통신 SDK를 쓰는 PC 프로그램(MES, 비전 보정, 모니터링) 개발 | 제조사별 통신 프로토콜 서버 (HSE, AS 터미널, Hi6 API, RWS, KukaVarProxy) |
| 로봇 프로그램이 PLC 신호와 맞물려 도는지 확인 | 5개 제조사 로봇 언어 실행 + 3D 확인 + 신호 타임라인 |
| 사이클 타임 대략 산정, 블렌딩 효과 비교 | 시뮬레이션 시계 기준 사이클 타임, 블렌딩 ON/OFF |
| 컨베이어·센서·실린더와 연동된 셀 시나리오 시험 | 셀 레이아웃 편집기, 주변기기가 로봇 I/O 로 연동 |

**하지 말아야 할 일**: 이 프로그램의 궤적·사이클 타임을 실제 설비의 확정 값으로 쓰는 것. 로봇 치수와 동특성은 근사값입니다 ([18장](#18-제한-사항--실제-로봇과-다른-점)).

## 2. 설치와 실행

### 2.1 필요 환경

- Node.js **20 이상** (https://nodejs.org 의 LTS 설치본)
- Windows · macOS · Linux 모두 같은 방법으로 설치합니다. 컴파일러나 OS 별 도구는 필요 없습니다.
- 브라우저: Chrome · Edge · Firefox 최신 버전 (WebGL 필요)

### 2.2 설치

```bash
git clone https://github.com/knoxxr/RobotEmulator
cd RobotEmulator
npm install
```

### 2.3 실행

```bash
npm start
```

콘솔에 다음과 같이 표시되면 브라우저에서 `http://localhost:3000` 을 엽니다.

```
  산업용 로봇 에뮬레이터  →  http://localhost:3000
  (바인딩: 모든 인터페이스 — 인증 없음, 신뢰할 수 있는 네트워크에서만 사용)

  [통신] Yaskawa High-Speed Ethernet Server udp   10040
  [통신] Kawasaki AS Terminal (telnet) tcp   23
  ...
  [통신] Modbus TCP Server            tcp   502
  [통신] OPC UA Server                opcua 4840
```

각 통신 인터페이스의 **실제 포트는 이 목록과 화면의 `통신` 탭에서 확인**합니다. 원하는 포트에 바인딩하지 못하면 대체 포트나 `(비활성)`으로 표시됩니다 ([17장](#17-문제-해결)).

### 2.4 포트·바인딩 주소 바꾸기

| 방법 | 예 |
|---|---|
| macOS / Linux | `PORT=3100 HOST=127.0.0.1 npm start` |
| Windows PowerShell | `$env:PORT=3100; $env:HOST="127.0.0.1"; npm start` |
| Windows cmd | `set PORT=3100 && set HOST=127.0.0.1 && npm start` |
| 설정 파일 | 루트에 `config.json` ([15장](#15-설정-파일-configjson)) |

우선순위: 기본값 < `config.json` < 환경변수.

### 2.5 PLC 와 연결할 때의 네트워크 구성

```
 [PLC / HMI / 상위 PC] ──(이더넷)── [에뮬레이터 PC : 192.168.0.10]
                                       ├ Modbus TCP 502
                                       ├ OPC UA 4840
                                       └ 제조사 프로토콜 (10040, 23, 8888, 8080, 7000)
```

1. 에뮬레이터 PC 의 IP 를 PLC 와 같은 대역으로 설정합니다.
2. `HOST` 를 지정하지 않고 실행합니다 (모든 인터페이스 바인딩).
3. Windows 는 처음 실행할 때 방화벽 허용 창에서 **허용**합니다. 이미 거부했다면 `Windows Defender 방화벽 → 앱 허용`에서 Node.js 를 허용합니다.
4. PLC 의 통신 설정에서 상대 IP 를 에뮬레이터 PC 로, 포트를 위 표의 값으로 지정합니다.

> **보안**: 웹 UI, API, 통신 인터페이스에는 인증이 없습니다. 접속할 수 있는 누구나 로봇을 움직이고 파일을 바꿀 수 있으므로 사내 시험망에서만 사용하십시오. 혼자 쓸 때는 `HOST=127.0.0.1`.

### 2.6 종료

터미널에서 `Ctrl+C` (Windows 는 `Ctrl+Break` 도 가능). 종료할 때 현재 상태를 자동 저장하고 통신 포트를 닫습니다. 다음 실행 시 직전 세션이 복원됩니다.

## 4. 5분 빠른 시작

1. `npm start` → 브라우저에서 `http://localhost:3000`.
2. 헤더에서 **제조사 · 모델**을 고릅니다. 현재 셀 배치에 맞는 pick & place 예제가 에디터에 자동으로 생성됩니다.
3. 모드가 TEACH 또는 PLAY 인지 확인하고 `Space` (또는 `▶ 시작`)를 누릅니다. 서보가 꺼져 있으면 자동으로 켜고 실행합니다. (REMOTE 모드에서는 화면에서 시작할 수 없습니다.)
4. 3D 뷰에서 로봇이 공작물 4개를 옮기는 것을 확인합니다. 끝나면 오른쪽 아래에 **사이클 타임**이 표시됩니다.
5. 통신을 확인하려면 `로봇` 탭에서 모드를 **REMOTE** 로 바꾸고, 새 터미널에서:
   ```bash
   node tools/clients/modbus-client.js 127.0.0.1 502
   ```
   상태 비트·관절각·TCP 를 읽고, DI 쓰기·오버라이드 변경·서보 ON·시작 명령을 보냅니다. REMOTE 가 아니면 서보 ON·시작이 `거부 (사유 코드 1)` 로 표시됩니다.

## 5. 로봇·그리퍼 설정

### 5.1 로봇 선택

헤더의 `제조사` → `모델`. 6개 제조사 85종(협동로봇 HC20DTP, 두산 M·H·A 시리즈 8종 포함)이 있으며 사양(가반하중, 도달거리, 관절 한계·속도, 출처)은 `로봇` 탭 아래 `로봇 사양`에 표시됩니다.

- 제조사를 바꾸면 해당 제조사의 언어·파일 형식·통신 표현으로 바뀝니다.
- 다른 제조사로 갔다가 돌아오면 이전에 작업하던 프로그램이 그대로 남아 있습니다.

### 5.2 컨트롤러 (`로봇` 탭)

| 항목 | 설명 |
|---|---|
| 서보 ON/OFF | OFF 이면 이동·프로그램 시작 불가 |
| 알람 리셋 | 알람이 남아 있으면 시작 불가 |
| HOME 이동 | 모델별 홈 자세로 관절 이동 |
| 모드 | TEACH / PLAY / REMOTE (펜던트 키 스위치에 해당). **외부(PLC·PC) 명령은 REMOTE 에서만 받습니다** — [9.2절](#92-안전--모드-인터록) |
| 간섭 체크 | OFF / 경고(표시만) / 정지(알람 정지). `간섭 모델 표시` 로 판정용 캡슐 확인 |
| 오버라이드 | 1~100 %. 로봇 속도 비율 (실제 컨트롤러의 속도 오버라이드) |
| 공작물 초기화 / 시작 시 자동 초기화 | 공작물을 셀의 초기 배치로 되돌림 |
| 궤적 표시 · 작업 영역 표시 | TCP 궤적 선, 손목 중심 도달 범위 점군 |

### 5.3 그리퍼 (`그리퍼` 탭)

- 라이브러리 15종(Robotiq, OnRobot, SCHUNK, Zimmer, 진공·자석·토치·스핀들) 중 선택.
- **STL 그리퍼**: STL 파일 + TCP(X/Y/Z), 종류(핑거/진공/자석), 행정, 단위(mm/m/inch).
- **그리퍼 I/O 할당**: 닫기 DO, 열기 DO, 닫힘 확인 DI, 열림 확인 DI, 공작물 감지 DI. 기본값은 DO1/DO2, DI1/DI2/DI3.

그리퍼는 DO 에 따라 열리고 닫히며, 닫힐 때 TCP 근처 공작물을 집습니다. 집은 공작물은 로봇을 따라 움직이고, 열면 아래로 떨어집니다. 확인 DI 는 실제 그리퍼처럼 동작 시간(0.4 초) 후에 바뀝니다.

## 6. 프로그램 작성과 실행

### 6.1 지원 언어

| 제조사 | 언어 | 파일 |
|---|---|---|
| Yaskawa | INFORM | `.JBI` |
| Kawasaki | AS | `.as` / `.pg` |
| Hyundai | HRScript | `.job` |
| ABB | RAPID | `.mod` |
| KUKA | KRL | `.src` + `.dat` |
| Doosan | DRL (파이썬 문법) | `.drl` / `.py` (메인은 `main.drl`) |

지원 문법의 상세 목록은 각 언어 모듈 상단 주석(`server/lang/*.js`)에 있습니다. 지원하지 않는 명령은 **컴파일 오류**로 알려 줍니다.

**DRL 참고:** 위치는 `posx(X, Y, Z, A, B, C)`(베이스 좌표, ZYZ 오일러)와 `posj(J1..J6)` 입니다. `movej` 속도는 `vel=`(deg/s) 또는 `set_velj()` 로 반드시 지정합니다. 다른 `.drl` 파일은 `sub_program_run("이름")` 으로 실행합니다. PC·비전 연동은 프로그램 안에서 `server_socket_open(포트)` / `client_socket_open(ip, 포트)` 로 TCP 소켓을 엽니다. 이 소켓은 프로그램이 끝나거나 정지하면 닫힙니다.

### 6.2 파일 다루기 (에디터 위 버튼)

| 버튼 | 동작 |
|---|---|
| `＋` | 새 파일 |
| `열기` | PC 의 파일을 불러옴 (여러 개 동시 가능, KRL 은 `.src` 와 `.dat` 를 함께) |
| `저장` | 저장 + 컴파일 (`Ctrl+S`) |
| `⭳` | 현재 파일 다운로드 (실제 컨트롤러에 옮길 때) |
| `메인` | 현재 파일을 시작 프로그램으로 지정 (★ 표시) |
| `삭제` | 현재 파일 삭제 |
| `예제` | 현재 로봇·셀에 맞는 예제 다시 생성 |

컴파일 결과는 에디터 아래에 표시되고, 오류가 있으면 해당 줄이 강조됩니다.

### 6.3 실행 제어

| 버튼 | 동작 |
|---|---|
| `▶ 시작` | 저장 → (서보 OFF 면 ON) → 처음부터 실행. 홀드 중이면 재개 |
| `⏭ 단계` | 한 줄씩 실행 |
| `⏸ 홀드` | 일시정지 (모션 감속 정지, 시뮬레이션 시계 정지). 다시 누르면 재개 |
| `■ 정지` | 프로그램 중단 |
| `⟲ 리셋` | 프로그램 포인터를 처음으로 |

실행 중인 줄은 에디터에서 노란색으로 표시되고, 호출된 서브 프로그램 파일로 자동 전환됩니다.

화면의 실행 버튼은 펜던트 조작에 해당하므로 TEACH · PLAY 모드에서만 동작합니다. REMOTE 모드에서는 PLC·상위 PC 의 시작 명령이나 시스템 I/O 시작 신호로만 시작합니다.

### 6.4 배속

`배속` 선택 상자(×0.1 ~ ×10) 또는 `-` / `+` 키.

- 모션, 대기(`WAIT`, `TIMER` 등), 타이머·펄스 출력, 컨베이어·실린더가 **모두 같은 비율**로 빨라지거나 느려집니다.
- 따라서 배속을 바꿔도 **궤적·블렌딩·사이클 타임 값은 1배속과 같습니다** (예: 14.06 초 사이클을 ×8 로 1.8 초 만에 확인).
- **조그는 항상 실시간**입니다.
- PLC 와 연동 시험할 때는 ×1 을 쓰십시오. 배속을 올리면 로봇 쪽 시간만 빨라지므로 PLC 의 타이머·타임아웃과 맞지 않습니다.

### 6.5 사이클 타임

- 시뮬레이션 시계 기준이므로 HOLD 시간과 PC 부하가 포함되지 않습니다.
- `상세 ▾`: 모션/대기/기타 비율, 줄별 소요 시간 상위 목록, 최근 이력.
- `블렌딩` 체크를 끄면 모든 경유점에서 정위치 정지 → 블렌딩 효과 비교.

## 8. 조그와 티칭

`조그` 탭:

- **축 조그**: 축별 `−` / `+` 버튼을 누르고 있는 동안 이동. 조그 속도 슬라이더(1~100 %).
- **직교 조그**: X/Y/Z/Rx/Ry/Rz, 좌표계 `BASE` / `TOOL`.
- 현재 위치는 제조사 표현(Yaskawa Rx·Ry·Rz, Kawasaki O·A·T, ABB 쿼터니언, KUKA A·B·C 등)으로 표시됩니다.
- 조그는 **TEACH 모드에서만** 됩니다 (모드 인터록 ON 일 때). `조그 시 인에이블 스위치 필요` 를 켜면 `인에이블` 버튼이 눌린 상태에서만 조그됩니다.

**티칭**: 에디터에서 커서를 놓고 `⌖ 현재위치 삽입` → 현재 자세가 해당 언어 문법의 이동 명령으로 삽입됩니다.

### 8.1 직접교시 (핸드 가이딩)

협동로봇을 손으로 끌어 가르치듯, 3D 화면에서 로봇을 마우스로 직접 움직입니다. 3D 뷰 아래의 `✋ 직접교시` 버튼(또는 `T` 키)으로 켭니다. 켜면 TEACH 모드와 서보 ON 으로 자동 전환됩니다.

| 조작 | 방법 |
|---|---|
| TCP 이동 | 툴 끝의 핸들에서 화살표(한 축) 또는 사각 평면(두 축)을 끌기 |
| TCP 회전 | `회전`(`E`) 으로 바꾼 뒤 링을 끌기 — TCP 위치는 유지 |
| 기준 좌표 | `BASE` = 로봇 베이스 좌표, `TOOL` = 툴 좌표 (`Q` 로 전환) |
| 관절 회전 | 로봇 링크에 마우스를 올리면 해당 관절 축에 링이 표시됨 → 잡고 관절 중심을 돌듯이 끌기. `Shift` 를 누르면 미세 조정 |
| 스냅 | 끔 / 1 mm·1° / 10 mm·5° (`X` 로 전환). 관절 드래그에도 각도 스냅 적용 |
| 되돌리기 | `↶` 또는 `Ctrl+Z` (드래그 단위로 최대 50단계) |
| 그리퍼 | `그리퍼 닫기/열기` 또는 `G` |
| 위치 기록 | `⌖ 위치 기록` 또는 `Enter` — 에디터 커서 위치에 이동 명령 삽입 (`⌖ 현재위치 삽입`과 같음) |

**가르치기 순서 예 (pick & place)**: 직접교시 켜기 → 공작물 위로 TCP 끌기 → `Enter`(접근점 기록) → 아래로 끌기 → `Enter` → `G`(그리퍼 닫기) → 위로 끌기 → `Enter` → … → `Esc` 로 끄고 기록된 명령의 속도·명령어를 다듬기.

로봇이 따라가지 못하는 동작은 거부되고 툴바 아래에 사유가 표시됩니다. 로봇은 마지막으로 가능했던 위치에 머뭅니다.

| 사유 | 의미 |
|---|---|
| 도달 불가 | 작업 영역·관절 한계 밖 |
| 자세 급변 | 특이점 부근이라 관절이 크게 뒤집혀야 하는 경우. 관절을 직접 끌어 자세를 바꾼 뒤 다시 시도 |
| 소프트 리밋 | 관절 한계에 닿음 |
| 간섭 | 간섭 체크 `정지` 모드에서 테이블·장애물·공작물에 닿기 직전. `경고` 모드에서는 들어가되 빨갛게 표시 |

직접교시는 조그와 같은 조건을 따릅니다: TEACH 모드, 서보 ON, 프로그램 정지 상태, 비상정지 아님, `인에이블 스위치 필요` 설정 시 인에이블 ON. 모드를 바꾸거나 프로그램을 시작하거나 비상정지하면 자동으로 꺼집니다.

## 9. I/O

`I/O` 탭:

- **DO (로봇 출력)**: 클릭하면 강제 출력.
- **DI (로봇 입력)**: 클릭하면 입력 시뮬레이션 (PLC 가 켠 것처럼).
- 표시 범위 1~128 (내부적으로는 1~512점).

같은 I/O 를 모든 통신 인터페이스가 공유합니다. 예: Modbus 코일 0 = DI1, 이산 입력 0 = DO1, OPC UA `IO/DI_1`, KUKA `$IN[1]`, Yaskawa HSE IO 명령.

### 9.1 I/O 이름표

PLC 의 I/O 할당표와 같은 이름을 붙여 두면 I/O 탭, 신호 타임라인에 함께 표시됩니다.

- I/O 탭에서 신호의 이름표를 편집합니다 (이름 + 설명).
- `이름표 CSV 내보내기 / 가져오기`: 열은 `type,n,name,desc` (type 은 `DI` 또는 `DO`). Excel 에서 열 수 있도록 UTF-8 BOM 으로 저장됩니다. PLC 태그 리스트를 이 형식으로 바꿔 가져오면 됩니다.
- 시스템 I/O 에 할당된 번호는 시스템 신호 이름이 우선 표시됩니다.
- 이름표는 프로젝트에 저장됩니다.

```csv
type,n,name,desc
DI,5,PART_PRESENT,지그 공작물 감지
DO,7,CLAMP,지그 클램프
```

### 9.2 안전 · 모드 인터록

실제 컨트롤러처럼 **명령을 누가 보냈는지**(펜던트 = 화면, 외부 = PLC·PC 통신과 시스템 I/O)와 운전 모드에 따라 명령을 받거나 거부합니다. `로봇` 탭 → `안전 · 인터록`.

**모드 인터록** (기본 ON)

| 모드 | 화면(펜던트) | 외부(PLC·PC·시스템 I/O) |
|---|---|---|
| TEACH | 서보 ON, 시작, 이동, 조그 가능 | 서보 ON · 시작 · 재개 · 이동 **거부** |
| PLAY | 서보 ON, 시작, 이동 가능 / 조그 거부 | 서보 ON · 시작 · 재개 · 이동 **거부** |
| REMOTE | 서보 ON 만 가능 / 시작 · 이동 · 조그 **거부** | 모두 가능 |

- 정지 · 홀드 · 알람 리셋 · I/O 쓰기 · 변수 쓰기 · 프로그램 파일 전송은 모드와 관계없이 받습니다.
- 운전 모드는 **화면에서만** 바꿀 수 있습니다 (키 스위치). OPC UA `Mode` 쓰기, RWS `opmode` 변경은 거부됩니다.
- TEACH ↔ PLAY/REMOTE 를 바꾸면 실행 중인 프로그램이 정지합니다.
- 모드 인터록을 끄면 위 제한이 모두 풀립니다 (안전 신호는 계속 적용). 기존 방식으로 빠르게 시험할 때만 쓰십시오.

**안전 신호** (인터록 설정과 관계없이 항상 적용)

| 신호 | 동작 | 복귀 |
|---|---|---|
| 비상정지 (헤더 버튼 또는 시스템 I/O 입력) | 정지 범주 0: 즉시 정지, 서보 OFF, `ESTOP` 알람. 프로그램 위치는 유지 | 비상정지 해제 → 알람 리셋 → 서보 ON → 시작(정지한 곳부터 재개) |
| 안전 펜스 열림 (자동 운전 중) | 정지 범주 1(기본): 정지 + 서보 OFF + `FENCE` 알람 / 정지 범주 2: 홀드만 | 펜스 닫기 → (알람 리셋 → 서보 ON) → 시작 |
| 안전 펜스 열림 (TEACH) | 영향 없음 | |
| 인에이블 스위치 (선택) | 꺼져 있으면 조그 거부 | 인에이블 ON |

원인이 남아 있는 동안(비상정지가 눌려 있거나 자동 모드에서 펜스가 열려 있는 동안)에는 알람 리셋이 되지 않습니다.

**거부 사유 코드** — 거부되면 화면 알림·로그에 표시되고, Modbus 입력 레지스터 7, OPC UA `LastRejectCode` / `LastRejectReason` 으로도 읽을 수 있습니다. 제조사 프로토콜은 각자의 오류 형식으로 응답합니다 (Yaskawa HSE 부가 상태 0x2080, RWS HTTP 400, AS `(P1013)…`, Hi6 HTTP 409, OPC UA `BadUserAccessDenied`).

| 코드 | 의미 | 코드 | 의미 |
|---|---|---|---|
| 1 | 외부 명령인데 REMOTE 가 아님 | 8 | 외부에서 모드 변경 시도 |
| 2 | REMOTE 에서 화면 시작·이동 | 9 | 프로그램 번호에 할당된 프로그램 없음 |
| 3 | 비상정지 중 | 10 | 프로그램 번호 패리티 오류 |
| 4 | 자동 모드에서 펜스 열림 | 11 | 조그는 TEACH 에서만 |
| 5 | 인에이블 OFF | 12 | 실행 중 프로그램 선택 |
| 6 | 알람 상태 | 13 | 외부 홀드 입력이 걸려 있음 |
| 7 | 서보 OFF | 14 | 서보 OFF 입력이 걸려 있음 |

### 9.3 시스템 I/O (전용 입출력)

실제 셀에서 PLC 는 보통 로봇의 **전용 입출력**(외부 서보 ON, 외부 시작, 프로그램 번호 선택, 운전 중·알람 출력 등)으로 로봇을 운전합니다. `시스템 I/O` 탭에서 이 신호를 범용 DI/DO 에 할당해 같은 시퀀스를 시험합니다.

1. `사용` 을 켜고 프리셋을 고릅니다: 범용, Yaskawa 전용 입출력, KUKA Automatic External, ABB System I/O, Kawasaki 전용 신호, Hyundai 원격 신호, Doosan 원격 제어 신호.
2. 신호 번호는 기본으로 DI 401번 · DO 401번부터 차례로 할당됩니다. 표에서 번호와 입력 논리(NC/NO)를 현장 설정에 맞게 바꿉니다.
3. `프로그램 번호` 표에 번호 → 프로그램 파일을 등록합니다. 표에 없으면 파일명이 같은 숫자인 프로그램(예: `0001.job` → 1)을 찾습니다.
4. 모드를 **REMOTE** 로 둡니다 (시스템 I/O 입력은 외부 명령입니다).
5. PLC 가 Modbus 코일(= DI) 로 입력을 쓰고, 이산 입력(= DO) 으로 출력을 읽습니다. 표의 램프를 눌러 PLC 입력을 흉내 낼 수도 있습니다.

**입력 동작**

| 종류 | 동작 |
|---|---|
| 서보 ON / 시작 / 처음부터 시작 / 정지 / 알람 리셋 / 프로그램 번호 스트로브 | 상승 에지(OFF→ON)에서 한 번 실행 |
| 서보 OFF (KUKA `$DRIVES_OFF`), 홀드 (KUKA `$MOVE_ENABLE`) | 레벨. NC 논리면 입력 OFF 일 때 동작 (서보 OFF / 홀드), 그동안 서보 ON·시작 거부 |
| 비상정지, 안전 펜스 | 레벨, 기본 NC (입력 OFF = 비상정지 / 펜스 열림) |
| 프로그램 번호 비트 (8비트 이진수), 패리티 (KUKA 홀수 패리티) | 스트로브 순간의 값을 읽음 |

`사용` 을 켜는 순간 NC 입력(비상정지 · 펜스 · `$DRIVES_OFF` · `$MOVE_ENABLE`)은 정상 상태(ON)로 놓입니다. 배선된 PLC 가 정상 신호를 주고 있는 상태와 같습니다.

**출력**: 운전 준비, 서보 ON 중, 운전 중, 홀드 중, 알람, REMOTE/TEACH/자동 모드, 홈 위치(±0.5°), 이동 중, 사이클 완료(다음 시작까지 유지), 프로그램 번호 요청 · 확인(0.3초 펄스) · 오류, 비상정지 정상/비상정지 중, 펜스 정상.

**예: KUKA Automatic External 시퀀스 (PLC 쪽)**

| 단계 | PLC 동작 | 로봇 응답 |
|---|---|---|
| 1 | `$DRIVES_OFF`, `$MOVE_ENABLE`, 비상정지, 펜스 입력 ON 유지 | `$ALARM_STOP`, `$USER_SAF` ON |
| 2 | `$CONF_MESS` 펄스 (알람 확인) | `$STOPMESS` OFF |
| 3 | `$DRIVES_ON` 펄스 | `$PERI_RDY` ON, `PGNO_REQ` ON |
| 4 | PGNO 비트 + `PGNO_PARITY` 설정 → `PGNO_VALID` 펄스 | `PGNO 확인` 펄스 (오류면 `PGNO 오류`) |
| 5 | `$EXT_START` 펄스 | `$PRO_ACT` ON |
| 6 | 완료 대기 | `사이클 완료` ON, `$PRO_ACT` OFF |

이 시퀀스는 자동 테스트(`test/interlock.test.js`)에서 Modbus 코일만으로 끝까지 검증합니다.

> 프리셋의 신호 이름·논리는 각 제조사의 일반적인 관례를 따른 **근사치**입니다. 실제 번호·NC/NO·펄스 폭은 컨트롤러 설정마다 다르므로 현장 할당표에 맞게 수정하십시오. KUKA 는 실제로는 `CELL.SRC` 가 PGNO 를 읽어 프로그램을 호출하지만, 에뮬레이터는 번호로 메인 프로그램을 바로 선택합니다.

## 10. 셀 레이아웃과 주변기기

`셀` 탭:

- **프리셋**: 기본 / 컨베이어 픽 앤 플레이스.
- **장치 추가·편집**: 테이블, 장애물, 공작물, 컨베이어, 피더, 센서, 공압 실린더, 배출구, 팔레트. 위치·크기·연동 I/O 를 편집.
- 장치는 로봇 I/O 로 연동됩니다 (기본: DO9 = 컨베이어 운전, DI9 = 도착 센서). 따라서 PLC 가 Modbus 로 컨베이어를 직접 제어하거나 센서를 읽는 시나리오도 시험할 수 있습니다.
- 장애물과 컨베이어 프레임은 간섭 체크 대상입니다.
- 레이아웃은 JSON 으로 내보내기/가져오기.

예제: `examples/conveyor/abb-irb1200/ConveyorPick.mod` (컨베이어 프리셋과 함께 사용).

## 12. 외부 통신 연동 (PLC·PC 개발)

### 12.1 공통 사항

- 모든 인터페이스는 **현재 선택된 제조사와 관계없이 동시에** 응답합니다 (데이터는 현재 로봇 기준).
- 실제 연동 대상과 같은 제조사 로봇을 선택해야 자세 표현·변수 이름·프로그램 언어가 맞습니다.
- 통신 탭에서 각 인터페이스의 실제 포트를 확인합니다.
- 각 인터페이스의 샘플 클라이언트가 `tools/clients/` 에 있습니다. 먼저 샘플로 접속을 확인한 뒤 자체 프로그램을 연결하십시오.

| 인터페이스 | 샘플 실행 |
|---|---|
| Modbus TCP | `node tools/clients/modbus-client.js 127.0.0.1 502` |
| OPC UA | `node tools/clients/opcua-client.js opc.tcp://127.0.0.1:4840/UA/RobotEmulator` |
| Yaskawa HSE | `node tools/clients/yaskawa-hse-client.js 127.0.0.1` |
| Kawasaki AS | `node tools/clients/kawasaki-as-client.js 127.0.0.1` |
| Hyundai API | `node tools/clients/hyundai-openapi-client.js 127.0.0.1` |
| ABB RWS | `node tools/clients/abb-rws-client.js 127.0.0.1` |
| KUKA VarProxy | `node tools/clients/kuka-varproxy-client.js 127.0.0.1` |

두 번째 인자로 포트를 지정할 수 있습니다. 대체 포트로 떴다면 예: `node tools/clients/kawasaki-as-client.js 127.0.0.1 10023`, `node tools/clients/modbus-client.js 127.0.0.1 1502`.

### 12.2 PLC 연동 — Modbus TCP

PLC 를 Modbus TCP **클라이언트(마스터)**로 설정하고 에뮬레이터를 서버로 지정합니다. Unit ID 는 아무 값이나 됩니다.

- 주소는 **0 기준**입니다. PLC 가 5자리 표기(40001 = 홀딩 0)를 쓰면 1을 빼서 맞추십시오.
- 32 bit 값은 **상위 워드 먼저**(빅 엔디언 워드 순서). PLC 의 워드 스왑 설정을 확인하십시오.

**대표 핸드셰이크 예 (PLC 쪽 로직)**

먼저 에뮬레이터 모드를 **REMOTE** 로 둡니다. 다른 모드에서는 서보 ON·시작 명령이 거부되고(결과 레지스터 Holding 2 = 1) 입력 레지스터 7 에 사유 코드가 남습니다.

| 단계 | PLC 동작 | 주소 |
|---|---|---|
| 1 | 로봇 준비 확인: REMOTE(b7), 비상정지 아님(b11=0), 알람 없음(b3=0) | Input Reg 0 |
| 2 | 서보 ON 명령 | Holding 0 ← 1, 결과 Holding 2 (0 정상) |
| 3 | 프로그램 시작 | Holding 0 ← 3 |
| 4 | 작업 요청 신호 | 코일 n (= 로봇 DI n+1) ON |
| 5 | 로봇 완료 신호 대기 | 이산 입력 m (= 로봇 DO m+1) |
| 6 | 사이클 시간 기록 | Input Reg 50-51 (ms) |
| 7 | 레시피·작업 번호 전달 | Holding 100.. (로봇 프로그램에서 레지스터 `MB:n` 으로 읽음) |
| 예외 | 명령이 거부되면 사유 확인 | Holding 2 = 1 이면 Input Reg 7 (거부 사유 코드, [9.2절](#92-안전--모드-인터록)) |

전용 입출력 방식(외부 시작 신호, 프로그램 번호 선택)을 쓰는 셀이라면 명령 레지스터 대신 [시스템 I/O](#93-시스템-io-전용-입출력) 를 켜고 코일로 시퀀스를 구동하십시오.

전체 주소 맵: [README › Modbus TCP 주소 맵](../README.md#modbus-tcp-주소-맵).

**국내 PLC 연결 요령**

| PLC | 설정 위치 (일반적인 예) |
|---|---|
| LS ELECTRIC XGT | XG5000 → FEnet 모듈 → P2P 설정 → Modbus TCP 클라이언트 |
| Mitsubishi iQ-R / Q | GX Works → 이더넷 설정 → 외부 기기 = Modbus/TCP (또는 FB 라이브러리) |
| Siemens S7-1200/1500 | TIA Portal `MB_CLIENT` 명령 |

> 실제 제조사 로봇은 Modbus 대신 PROFINET · EtherNet/IP · CC-Link 같은 필드버스나 하드와이어 I/O 를 쓰는 경우가 많습니다. 이 에뮬레이터의 Modbus 는 **로직 개발용 대체 경로**이므로, 실제 장비에서는 같은 신호를 해당 필드버스의 I/O 맵에 옮겨야 합니다.

### 12.5 연동 시험 순서 (권장)

1. **로봇 측 확인**: 해당 제조사 로봇을 선택하고 예제 프로그램이 끝까지 도는지 확인 (TEACH/PLAY 에서 화면으로 시작). 이후 모드를 REMOTE 로.
2. **접속 확인**: 샘플 클라이언트로 상태 읽기.
3. **읽기 연동**: 자체 프로그램으로 상태·위치·I/O 를 읽고 화면 값과 비교.
4. **쓰기 연동**: DI 쓰기, 변수 쓰기 → 에뮬레이터 `I/O` 탭 · `변수` 탭에서 반영 확인.
5. **제어 연동**: 서보 ON, 시작, 홀드, 정지, 알람 리셋.
6. **시나리오 시험**: 로봇 프로그램과 PLC 로직을 함께 돌리며 신호 타임라인으로 핸드셰이크 확인.
7. **이상 상황**: 실행 중 비상정지(헤더 버튼 또는 비상정지 입력), 안전 펜스 열기, 모드를 TEACH 로 바꾸기(실행 정지), `■ 정지`, 간섭 알람 유발, 통신 끊김(에뮬레이터 종료) 등에 대한 PLC 측 처리와 복귀 시퀀스를 확인.

## 15. 설정 파일 (config.json)

프로젝트 루트에 만듭니다. 지정하지 않은 항목은 기본값을 씁니다.

```json
{
  "httpPort": 3000,
  "host": "127.0.0.1",
  "robot": "kuka-kr6-r900",
  "gripper": "robotiq-2f85",
  "restoreSession": true,
  "protocols": {
    "yaskawaHse":   { "port": 10040, "filePort": 10041 },
    "kawasakiAs":   { "port": 23, "fallbackPort": 10023 },
    "hyundai":      { "port": 8888 },
    "abbRws":       { "port": 8080 },
    "kukaVarProxy": { "port": 7000 },
    "modbus":       { "port": 502, "fallbackPort": 1502 },
    "opcua":        { "port": 4840 }
  },
  "ai": { "model": "claude-opus-5-5", "effort": "high" }
}
```

| 키 | 설명 |
|---|---|
| `httpPort` | 웹 UI·REST·WebSocket·MCP 포트 (환경변수 `PORT` 가 우선) |
| `host` | 바인딩 주소. 기본 `"127.0.0.1"` = 이 PC 만, `"0.0.0.0"` = 모든 인터페이스(다른 PC·PLC 접속) (환경변수 `HOST` 가 우선). 통신 모듈에도 적용 |
| `allowedHosts` | 웹 UI·API 를 IP 가 아닌 호스트 이름으로 접속할 때 허용할 이름 목록 (예: `["robot-pc.local"]`). localhost·IP 주소는 항상 허용 |
| `robot`, `gripper` | 시작 시 로봇·그리퍼. `robot` 을 지정하면 자동 저장 복원을 하지 않음 |
| `restoreSession` | `false` 면 직전 세션 복원 안 함 |
| `protocols.<키>.enabled` | `false` 면 해당 인터페이스 끔 |
| `protocols.<키>.port` / `fallbackPort` | 포트 / 바인딩 실패 시 대체 포트 |
| `protocols.<키>.host` | 해당 인터페이스만 다른 바인딩 주소 |

## 16. 공용 REST / WebSocket API

자체 시험 자동화 스크립트에서 에뮬레이터를 직접 제어할 때 씁니다.

- `GET /api/state` — 전체 상태 스냅샷 (관절, TCP, I/O, 프로그램, 알람, 사이클, 배속 …)
- `GET /api/robots` — 로봇·그리퍼·제조사 목록
- `GET /api/comms` — 통신 인터페이스와 실제 포트
- `POST /api/cmd` — JSON `{ "cmd": "...", ... }` (`Content-Type: application/json` 필수. 다른 웹사이트에서 보낸 브라우저 요청은 403). 이 API 는 **펜던트(화면)와 같은 출처**로 취급되어 모드 인터록이 그대로 적용됩니다 (예: REMOTE 에서 `start` 거부).
- `ws://<host>:3000/ws` — 같은 명령을 `{ "cmd": "...", "id": 1 }` 로 보내면 `{ type: "reply", id: 1, ok }` 응답. 상태(`state`, 최대 30 Hz)·로그·타임라인 이벤트가 푸시됨. `state` 에서 `sysio`·`cell`·`scene`·`safety`·`ioLabels`·`gripperIO`·`cameras` 는 직전 전송과 같으면 생략되므로 이전 값을 유지해 쓰십시오 (전체 상태는 접속 시 `init` 또는 `{"cmd":"state"}`). 로그는 100 ms 단위로 묶여 `log`(1개) 또는 `logs`(`entries` 배열)로 옵니다

| cmd | 인자 | 동작 |
|---|---|---|
| `setRobot` | `id` | 로봇 변경 |
| `setGripper` | `id` | 그리퍼 변경 |
| `servo` | `on` | 서보 ON/OFF |
| `mode` | `mode` (TEACH/PLAY/REMOTE) | 모드 (펜던트 키 스위치) |
| `safety` | `estop`, `fence`, `enable`, `requireEnable`, `fenceStop` (`stop1`/`stop2`), `interlock` | 안전 신호 · 인터록 설정 |
| `sysio` | `op: "presets"` 또는 `op: "set", config: { enabled, preset, diBase, doBase, assign, logic, programs }` | 시스템 I/O |
| `ioLabel` / `ioLabels` | `type`, `n`, `name`, `desc` / `labels` | I/O 이름표 |
| `override` | `value` (1~100) | 오버라이드 |
| `timeScale` | `value` (0.1~10) | 배속 |
| `moveJoints` | `joints[6]`, `speed` (0~1) | 관절 이동 |
| `teachPose` | `p` [x,y,z] mm, `q` [w,x,y,z] (로봇 베이스 기준 TCP) | 직접교시: TCP 를 즉시 그 자세로 (조그 조건). 결과 `{ ok, joints \| reason }` |
| `teachJoints` / `setJoints` | `joints[6]` | 직접교시: 관절각 즉시 지정 (조그 조건) |
| `moveHome` | | 홈 이동 |
| `setDO` / `setDI` | `n`, `v` | I/O 쓰기 |
| `saveFile` / `deleteFile` / `setMain` | `name`, `text` | 프로그램 파일 |
| `start` / `step` / `hold` / `resume` / `stop` / `reset` | | 실행 제어 |
| `resetAlarms` / `resetScene` | | 알람 리셋 / 공작물 초기화 |
| `breakpoints` | `list` (`"파일:줄"`) | 브레이크포인트 |
| `vars` / `timeline` / `timelineClear` | | 변수 / 신호 타임라인 |
| `cell` | `op`, … | 셀 레이아웃 (`get`/`set`/`preset`/`resetObjects`/`add`/`remove`/`update`) |
| `projectSave` / `projectLoad` / `projectExport` / `projectImport` | `name` / `project` | 프로젝트 |
| `state` | | 상태 스냅샷 |

예 (PowerShell 에서는 `curl.exe`):

```bash
curl -X POST http://localhost:3000/api/cmd -H "Content-Type: application/json" -d '{"cmd":"setDI","n":5,"v":true}'
```

## 17. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| `HTTP 서버 시작 실패 … 포트가 이미 사용 중` | 다른 프로그램(또는 이미 실행 중인 에뮬레이터)이 3000 번 사용 중. `PORT=3100 npm start` |
| Kawasaki 가 10023, Modbus 가 1502 로 뜸 | Linux/macOS 에서 1024 미만 포트는 관리자 권한 필요 → 자동 대체. 원래 포트가 필요하면 관리자 권한 실행 또는 `sudo setcap 'cap_net_bind_service=+ep' "$(command -v node)"` |
| 통신 탭에 `(비활성)` | 포트 충돌. 로그의 `통신` 항목에서 원인 확인 후 `config.json` 에서 포트 변경 |
| 다른 PC·PLC 에서 접속 안 됨 | ① `HOST=127.0.0.1` 로 실행하지 않았는지 ② 방화벽 허용 ③ 같은 IP 대역 ④ `ping` 확인 |
| OPC UA 접속 시 인증서 경고 | 자체 서명 인증서. 클라이언트에서 서버 인증서를 신뢰. 인증서를 새로 만들려면 `.opcua-pki/` 삭제 후 재시작 |
| `시작` 해도 동작 안 함 | 화면 알림·로그의 거부 사유 확인: REMOTE 모드 → TEACH/PLAY 로, 비상정지 → 해제 후 알람 리셋, `알람 리셋 후 시작하십시오` → 알람 리셋, `서보 OFF` → 서보 ON, 컴파일 오류 → 에디터 아래 메시지 |
| PLC 의 서보 ON·시작 명령이 거부됨 | 모드가 REMOTE 인지, 비상정지·펜스 상태 확인. Modbus 는 입력 레지스터 7 에 사유 코드 |
| 조그가 안 됨 | TEACH 모드인지, `인에이블 스위치 필요` 가 켜져 있으면 인에이블 ON |
| 시스템 I/O 를 켜자 로봇이 서보 OFF·홀드됨 | NC 입력(`$DRIVES_OFF`, `$MOVE_ENABLE`, 비상정지, 펜스)이 OFF 로 바뀌었는지 확인. PLC 가 이 입력들을 ON 으로 유지해야 함 |
| 프로그램 번호를 보내도 선택 안 됨 | `프로그램 번호` 표 등록 여부, 패리티(KUKA 홀수), 실행 중이 아닌지 확인. 실패 시 `프로그램 번호 오류` 출력 ON |
| `목표 위치에 도달할 수 없습니다` 알람 | 작업 영역·관절 한계 밖. `작업 영역 표시`로 범위 확인 |
| 로봇이 테이블 앞에서 멈추고 `COLLISION` 알람 | 간섭 체크 `정지` 모드. `알람 리셋` 후 조그로 빠져나오거나 간섭 모드를 `경고`로 |
| 3D 화면이 검거나 느림 | 브라우저 하드웨어 가속(WebGL) 확인. 저사양 PC 는 `궤적 표시`·`작업 영역 표시` 끄기 |
| 서버 재시작 후 이전 상태가 아님 | `config.json` 에 `robot` 을 지정했거나 `restoreSession: false` |

## 18. 제한 사항 — 실제 로봇과 다른 점

PLC·PC 개발에 영향을 주는 순서로 정리했습니다.

1. **모드 인터록 · 안전 · 시스템 I/O 는 단순화 모델**: 인터록 규칙은 제조사 공통으로 단순화했고, 시스템 I/O 프리셋은 관례를 따른 근사치입니다. 안전 회로의 이중화, 감시 정지 시간, TEACH 모드 감속(250 mm/s 제한), 브레이크 정지 거리는 모사하지 않습니다.
2. **필드버스**: PROFINET · EtherNet/IP · EtherCAT · CC-Link 는 지원하지 않습니다 (Modbus TCP / OPC UA 로 대체).
3. **프로토콜 검증 수준**: 각 프로토콜은 공개 매뉴얼 기반이며 실제 컨트롤러와 바이트 단위로 대조하지 않은 부분이 있습니다. 특히 Hyundai Hi6 API 경로, Yaskawa HSE 부가 상태 코드.
4. **알람 코드**: 알람 번호·메시지는 실제 제조사 코드 체계와 다릅니다.
5. **로봇 치수·동특성**: 공개 카탈로그 기반 근사값. 가반하중에 따른 가감속, 브레이크 정지 거리 미반영. 사이클 타임은 참고값.
6. **통신 타이밍**: 응답은 거의 즉시 옵니다. 실제 컨트롤러의 응답 지연·처리 주기·동시 접속 제한은 모사하지 않습니다.
7. **간섭 체크**: 캡슐 근사로 실제 외형과 수 mm ~ 수십 mm 차이.
8. **보안**: 인증 없음.

개선 계획은 [ROADMAP-SI.md](ROADMAP-SI.md) 를 참고하십시오.
