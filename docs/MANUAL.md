## 1. 이 프로그램으로 할 수 있는 일

Yaskawa · Kawasaki · Hyundai · ABB · KUKA 로봇 컨트롤러를 **하나의 가상 컨트롤러**로 흉내 냅니다.

| 하고 싶은 일 | 이 프로그램에서 |
|---|---|
| 로봇이 입고되기 전에 PLC 인터록·핸드셰이크 로직을 짜고 시험 | Modbus TCP / OPC UA 서버, DI/DO 512점, 상태·명령 레지스터 |
| 제조사 통신 SDK를 쓰는 PC 프로그램(MES, 비전 보정, 모니터링) 개발 | 제조사별 통신 프로토콜 서버 (HSE, AS 터미널, Hi6 API, RWS, KukaVarProxy) |
| 로봇 프로그램이 PLC 신호와 맞물려 도는지 확인 | 5개 제조사 로봇 언어 실행 + 3D 확인 + 신호 타임라인 |
| 사이클 타임 대략 산정, 블렌딩 효과 비교 | 시뮬레이션 시계 기준 사이클 타임, 블렌딩 ON/OFF |
| 컨베이어·센서·실린더와 연동된 셀 시나리오 시험 | 셀 레이아웃 편집기, 주변기기가 로봇 I/O 로 연동 |

**하지 말아야 할 일**: 이 프로그램의 궤적·사이클 타임을 실제 설비의 확정 값으로 쓰는 것. 로봇 치수와 동특성은 근사값입니다 ([18장](#18-제한-사항--실제-로봇과-다른-점)).

## 2. 설치와 실행

### 2.1 필요 환경

- Node.js **20 이상** (https://nodejs.org 의 LTS 설치본)
- Windows · macOS · Linux 모두 같은 방법으로 설치합니다. 컴파일러나 OS 별 도구는 필요 없습니다.
- 브라우저: Chrome · Edge · Firefox 최신 버전 (WebGL 필요)

### 2.2 설치

```bash
git clone https://github.com/knoxxr/RobotEmulator
cd RobotEmulator
npm install
```

### 2.3 실행

```bash
npm start
```

콘솔에 다음과 같이 표시되면 브라우저에서 `http://localhost:3000` 을 엽니다.

```
  산업용 로봇 에뮬레이터  →  http://localhost:3000
  (바인딩: 모든 인터페이스 — 인증 없음, 신뢰할 수 있는 네트워크에서만 사용)

  [통신] Yaskawa High-Speed Ethernet Server udp   10040
  [통신] Kawasaki AS Terminal (telnet) tcp   23
  ...
  [통신] Modbus TCP Server            tcp   502
  [통신] OPC UA Server                opcua 4840
```

각 통신 인터페이스의 **실제 포트는 이 목록과 화면의 `통신` 탭에서 확인**합니다. 원하는 포트에 바인딩하지 못하면 대체 포트나 `(비활성)`으로 표시됩니다 ([17장](#17-문제-해결)).

### 2.4 포트·바인딩 주소 바꾸기

| 방법 | 예 |
|---|---|
| macOS / Linux | `PORT=3100 HOST=127.0.0.1 npm start` |
| Windows PowerShell | `$env:PORT=3100; $env:HOST="127.0.0.1"; npm start` |
| Windows cmd | `set PORT=3100 && set HOST=127.0.0.1 && npm start` |
| 설정 파일 | 루트에 `config.json` ([15장](#15-설정-파일-configjson)) |

우선순위: 기본값 < `config.json` < 환경변수.

### 2.5 PLC 와 연결할 때의 네트워크 구성

```
 [PLC / HMI / 상위 PC] ──(이더넷)── [에뮬레이터 PC : 192.168.0.10]
                                       ├ Modbus TCP 502
                                       ├ OPC UA 4840
                                       └ 제조사 프로토콜 (10040, 23, 8888, 8080, 7000)
```

1. 에뮬레이터 PC 의 IP 를 PLC 와 같은 대역으로 설정합니다.
2. `HOST` 를 지정하지 않고 실행합니다 (모든 인터페이스 바인딩).
3. Windows 는 처음 실행할 때 방화벽 허용 창에서 **허용**합니다. 이미 거부했다면 `Windows Defender 방화벽 → 앱 허용`에서 Node.js 를 허용합니다.
4. PLC 의 통신 설정에서 상대 IP 를 에뮬레이터 PC 로, 포트를 위 표의 값으로 지정합니다.

> **보안**: 웹 UI, API, 통신 인터페이스에는 인증이 없습니다. 접속할 수 있는 누구나 로봇을 움직이고 파일을 바꿀 수 있으므로 사내 시험망에서만 사용하십시오. 혼자 쓸 때는 `HOST=127.0.0.1`.

### 2.6 종료

터미널에서 `Ctrl+C` (Windows 는 `Ctrl+Break` 도 가능). 종료할 때 현재 상태를 자동 저장하고 통신 포트를 닫습니다. 다음 실행 시 직전 세션이 복원됩니다.

## 3. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 헤더: 제조사 · 모델 · 그리퍼 선택 | 📁 프로젝트 | ✦ Claude | 연결·서보·모드·상태 표시 │
├────────────────┬────────────────────────────────────┬────────────────────────┤
│ 왼쪽 패널 (탭)  │ 3D 뷰                               │ 프로그램 에디터          │
│ 로봇 · 그리퍼   │  좌상: 관절각·TCP 자세·그리퍼         │  파일 탭 · 열기·저장 …   │
│ 조그 · I/O     │  우상: 프로그램·상태·사이클·OV·배속    │  실행 라인 강조          │
│ 통신 · 셀      │  좌하: 알람                          │ 시작·단계·홀드·정지·리셋 │
│ 카메라         │                                     │ 배속 · 사이클 타임       │
├────────────────┴────────────────────────────────────┴────────────────────────┤
│ 하단: 로그 | 신호 타임라인 | 변수                                                │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 내용 |
|---|---|
| 헤더 상태 표시 | `연결됨`(브라우저↔서버), `SERVO ON/OFF`, 모드(TEACH/PLAY/REMOTE), 프로그램 상태(IDLE/RUNNING/…), 간섭, ALARM |
| 3D 뷰 | 마우스 왼쪽 드래그 = 회전, 오른쪽 드래그 = 이동, 휠 = 확대/축소. `로봇` 탭의 `시점 초기화` 로 되돌림 |
| 하단 로그 | 출처별 필터: 시스템 · 프로그램 · 그리퍼 · 통신 · 알람 |

### 단축키

| 키 | 동작 | 비고 |
|---|---|---|
| `Space` | 시작 / 홀드 / 재개 (토글) | 에디터·입력칸에 포커스가 있으면 무시 |
| `-` / `+` | 배속 한 단계 낮춤 / 높임 | 같은 조건 |
| `Ctrl+S` | 모든 파일 저장 + 컴파일 | |

## 4. 5분 빠른 시작

1. `npm start` → 브라우저에서 `http://localhost:3000`.
2. 헤더에서 **제조사 · 모델**을 고릅니다. 현재 셀 배치에 맞는 pick & place 예제가 에디터에 자동으로 생성됩니다.
3. `Space` (또는 `▶ 시작`)를 누릅니다. 서보가 꺼져 있으면 자동으로 켜고 실행합니다.
4. 3D 뷰에서 로봇이 공작물 4개를 옮기는 것을 확인합니다. 끝나면 오른쪽 아래에 **사이클 타임**이 표시됩니다.
5. 통신을 확인하려면 새 터미널에서:
   ```bash
   node tools/clients/modbus-client.js 127.0.0.1 502
   ```
   상태 비트·관절각·TCP 를 읽고, DI 쓰기·오버라이드 변경·서보 ON·시작 명령을 보냅니다.

## 5. 로봇·그리퍼 설정

### 5.1 로봇 선택

헤더의 `제조사` → `모델`. 17종이 있으며 사양(가반하중, 도달거리, 관절 한계·속도, 출처)은 `로봇` 탭 아래 `로봇 사양`에 표시됩니다.

- 제조사를 바꾸면 해당 제조사의 언어·파일 형식·통신 표현으로 바뀝니다.
- 다른 제조사로 갔다가 돌아오면 이전에 작업하던 프로그램이 그대로 남아 있습니다.

### 5.2 컨트롤러 (`로봇` 탭)

| 항목 | 설명 |
|---|---|
| 서보 ON/OFF | OFF 이면 이동·프로그램 시작 불가 |
| 알람 리셋 | 알람이 남아 있으면 시작 불가 |
| HOME 이동 | 모델별 홈 자세로 관절 이동 |
| 모드 | TEACH / PLAY / REMOTE. 통신 인터페이스의 모드 표시값(예: KUKA `$MODE_OP`, Modbus 상태 비트 b5~b7)에 반영됨. **현재는 모드에 따른 동작 제한이 없음** ([18장](#18-제한-사항--실제-로봇과-다른-점)) |
| 간섭 체크 | OFF / 경고(표시만) / 정지(알람 정지). `간섭 모델 표시` 로 판정용 캡슐 확인 |
| 오버라이드 | 1~100 %. 로봇 속도 비율 (실제 컨트롤러의 속도 오버라이드) |
| 공작물 초기화 / 시작 시 자동 초기화 | 공작물을 셀의 초기 배치로 되돌림 |
| 궤적 표시 · 작업 영역 표시 | TCP 궤적 선, 손목 중심 도달 범위 점군 |

### 5.3 그리퍼 (`그리퍼` 탭)

- 라이브러리 15종(Robotiq, OnRobot, SCHUNK, Zimmer, 진공·자석·토치·스핀들) 중 선택.
- **STL 그리퍼**: STL 파일 + TCP(X/Y/Z), 종류(핑거/진공/자석), 행정, 단위(mm/m/inch).
- **그리퍼 I/O 할당**: 닫기 DO, 열기 DO, 닫힘 확인 DI, 열림 확인 DI, 공작물 감지 DI. 기본값은 DO1/DO2, DI1/DI2/DI3.

그리퍼는 DO 에 따라 열리고 닫히며, 닫힐 때 TCP 근처 공작물을 집습니다. 집은 공작물은 로봇을 따라 움직이고, 열면 아래로 떨어집니다. 확인 DI 는 실제 그리퍼처럼 동작 시간(0.4 초) 후에 바뀝니다.

## 6. 프로그램 작성과 실행

### 6.1 지원 언어

| 제조사 | 언어 | 파일 |
|---|---|---|
| Yaskawa | INFORM | `.JBI` |
| Kawasaki | AS | `.as` / `.pg` |
| Hyundai | HRScript | `.job` |
| ABB | RAPID | `.mod` |
| KUKA | KRL | `.src` + `.dat` |

지원 문법의 상세 목록은 각 언어 모듈 상단 주석(`server/lang/*.js`)에 있습니다. 지원하지 않는 명령은 **컴파일 오류**로 알려 줍니다.

### 6.2 파일 다루기 (에디터 위 버튼)

| 버튼 | 동작 |
|---|---|
| `＋` | 새 파일 |
| `열기` | PC 의 파일을 불러옴 (여러 개 동시 가능, KRL 은 `.src` 와 `.dat` 를 함께) |
| `저장` | 저장 + 컴파일 (`Ctrl+S`) |
| `⭳` | 현재 파일 다운로드 (실제 컨트롤러에 옮길 때) |
| `메인` | 현재 파일을 시작 프로그램으로 지정 (★ 표시) |
| `삭제` | 현재 파일 삭제 |
| `예제` | 현재 로봇·셀에 맞는 예제 다시 생성 |

컴파일 결과는 에디터 아래에 표시되고, 오류가 있으면 해당 줄이 강조됩니다.

### 6.3 실행 제어

| 버튼 | 동작 |
|---|---|
| `▶ 시작` | 저장 → (서보 OFF 면 ON) → 처음부터 실행. 홀드 중이면 재개 |
| `⏭ 단계` | 한 줄씩 실행 |
| `⏸ 홀드` | 일시정지 (모션 감속 정지, 시뮬레이션 시계 정지). 다시 누르면 재개 |
| `■ 정지` | 프로그램 중단 |
| `⟲ 리셋` | 프로그램 포인터를 처음으로 |

실행 중인 줄은 에디터에서 노란색으로 표시되고, 호출된 서브 프로그램 파일로 자동 전환됩니다.

### 6.4 배속

`배속` 선택 상자(×0.1 ~ ×10) 또는 `-` / `+` 키.

- 모션, 대기(`WAIT`, `TIMER` 등), 타이머·펄스 출력, 컨베이어·실린더가 **모두 같은 비율**로 빨라지거나 느려집니다.
- 따라서 배속을 바꿔도 **궤적·블렌딩·사이클 타임 값은 1배속과 같습니다** (예: 14.06 초 사이클을 ×8 로 1.8 초 만에 확인).
- **조그는 항상 실시간**입니다.
- PLC 와 연동 시험할 때는 ×1 을 쓰십시오. 배속을 올리면 로봇 쪽 시간만 빨라지므로 PLC 의 타이머·타임아웃과 맞지 않습니다.

### 6.5 사이클 타임

- 시뮬레이션 시계 기준이므로 HOLD 시간과 PC 부하가 포함되지 않습니다.
- `상세 ▾`: 모션/대기/기타 비율, 줄별 소요 시간 상위 목록, 최근 이력.
- `블렌딩` 체크를 끄면 모든 경유점에서 정위치 정지 → 블렌딩 효과 비교.

## 7. 디버깅

| 기능 | 사용법 |
|---|---|
| 브레이크포인트 | 에디터 줄 번호 클릭. 그 줄을 실행하기 직전에 멈춤 → `▶ 시작` 또는 `⏭ 단계`로 계속 |
| 변수 감시 (`변수` 탭) | 로컬·전역·레지스터 값. 바뀐 값은 강조 |
| 신호 타임라인 (`신호 타임라인` 탭) | DO/DI, RUN, MOVING, HOLD, GRIP, ALARM 파형. 두 지점을 클릭하면 Δt 측정 |
| 로그 | `통신` 필터로 외부 인터페이스 요청 기록 확인 (같은 메시지는 3 초에 한 번만 표시) |

**PLC 핸드셰이크 타이밍 확인 예**: 신호 타임라인에서 로봇이 DO(작업 완료)를 켠 시점과 PLC 가 DI(다음 작업 허가)를 켠 시점을 클릭해 응답 지연을 측정합니다.

## 8. 조그와 티칭

`조그` 탭:

- **축 조그**: 축별 `−` / `+` 버튼을 누르고 있는 동안 이동. 조그 속도 슬라이더(1~100 %).
- **직교 조그**: X/Y/Z/Rx/Ry/Rz, 좌표계 `BASE` / `TOOL`.
- 현재 위치는 제조사 표현(Yaskawa Rx·Ry·Rz, Kawasaki O·A·T, ABB 쿼터니언, KUKA A·B·C 등)으로 표시됩니다.

**티칭**: 에디터에서 커서를 놓고 `⌖ 현재위치 삽입` → 현재 자세가 해당 언어 문법의 이동 명령으로 삽입됩니다.

---

## 9. I/O

`I/O` 탭:

- **DO (로봇 출력)**: 클릭하면 강제 출력.
- **DI (로봇 입력)**: 클릭하면 입력 시뮬레이션 (PLC 가 켠 것처럼).
- 표시 범위 1~128 (내부적으로는 1~512점).

같은 I/O 를 모든 통신 인터페이스가 공유합니다. 예: Modbus 코일 0 = DI1, 이산 입력 0 = DO1, OPC UA `IO/DI_1`, KUKA `$IN[1]`, Yaskawa HSE IO 명령.

## 10. 셀 레이아웃과 주변기기

`셀` 탭:

- **프리셋**: 기본 / 컨베이어 픽 앤 플레이스.
- **장치 추가·편집**: 테이블, 장애물, 공작물, 컨베이어, 피더, 센서, 공압 실린더, 배출구, 팔레트. 위치·크기·연동 I/O 를 편집.
- 장치는 로봇 I/O 로 연동됩니다 (기본: DO9 = 컨베이어 운전, DI9 = 도착 센서). 따라서 PLC 가 Modbus 로 컨베이어를 직접 제어하거나 센서를 읽는 시나리오도 시험할 수 있습니다.
- 장애물과 컨베이어 프레임은 간섭 체크 대상입니다.
- 레이아웃은 JSON 으로 내보내기/가져오기.

예제: `examples/conveyor/abb-irb1200/ConveyorPick.mod` (컨베이어 프리셋과 함께 사용).

## 12. 외부 통신 연동 (PLC·PC 개발)

### 12.1 공통 사항

- 모든 인터페이스는 **현재 선택된 제조사와 관계없이 동시에** 응답합니다 (데이터는 현재 로봇 기준).
- 실제 연동 대상과 같은 제조사 로봇을 선택해야 자세 표현·변수 이름·프로그램 언어가 맞습니다.
- 통신 탭에서 각 인터페이스의 실제 포트를 확인합니다.
- 각 인터페이스의 샘플 클라이언트가 `tools/clients/` 에 있습니다. 먼저 샘플로 접속을 확인한 뒤 자체 프로그램을 연결하십시오.

| 인터페이스 | 샘플 실행 |
|---|---|
| Modbus TCP | `node tools/clients/modbus-client.js 127.0.0.1 502` |
| OPC UA | `node tools/clients/opcua-client.js opc.tcp://127.0.0.1:4840/UA/RobotEmulator` |
| Yaskawa HSE | `node tools/clients/yaskawa-hse-client.js 127.0.0.1` |
| Kawasaki AS | `node tools/clients/kawasaki-as-client.js 127.0.0.1` |
| Hyundai API | `node tools/clients/hyundai-openapi-client.js 127.0.0.1` |
| ABB RWS | `node tools/clients/abb-rws-client.js 127.0.0.1` |
| KUKA VarProxy | `node tools/clients/kuka-varproxy-client.js 127.0.0.1` |

두 번째 인자로 포트를 지정할 수 있습니다. 대체 포트로 떴다면 예: `node tools/clients/kawasaki-as-client.js 127.0.0.1 10023`, `node tools/clients/modbus-client.js 127.0.0.1 1502`.

### 12.2 PLC 연동 — Modbus TCP

PLC 를 Modbus TCP **클라이언트(마스터)**로 설정하고 에뮬레이터를 서버로 지정합니다. Unit ID 는 아무 값이나 됩니다.

- 주소는 **0 기준**입니다. PLC 가 5자리 표기(40001 = 홀딩 0)를 쓰면 1을 빼서 맞추십시오.
- 32 bit 값은 **상위 워드 먼저**(빅 엔디언 워드 순서). PLC 의 워드 스왑 설정을 확인하십시오.

**대표 핸드셰이크 예 (PLC 쪽 로직)**

| 단계 | PLC 동작 | 주소 |
|---|---|---|
| 1 | 로봇 준비 확인: 서보 ON(b0), 알람 없음(b3=0) | Input Reg 0 |
| 2 | 서보 ON 명령 | Holding 0 ← 1, 결과 Holding 2 (0 정상) |
| 3 | 프로그램 시작 | Holding 0 ← 3 |
| 4 | 작업 요청 신호 | 코일 n (= 로봇 DI n+1) ON |
| 5 | 로봇 완료 신호 대기 | 이산 입력 m (= 로봇 DO m+1) |
| 6 | 사이클 시간 기록 | Input Reg 50-51 (ms) |
| 7 | 레시피·작업 번호 전달 | Holding 100.. (로봇 프로그램에서 레지스터 `MB:n` 으로 읽음) |

전체 주소 맵: [README › Modbus TCP 주소 맵](../README.md#modbus-tcp-주소-맵).

**국내 PLC 연결 요령**

| PLC | 설정 위치 (일반적인 예) |
|---|---|
| LS ELECTRIC XGT | XG5000 → FEnet 모듈 → P2P 설정 → Modbus TCP 클라이언트 |
| Mitsubishi iQ-R / Q | GX Works → 이더넷 설정 → 외부 기기 = Modbus/TCP (또는 FB 라이브러리) |
| Siemens S7-1200/1500 | TIA Portal `MB_CLIENT` 명령 |

> 실제 제조사 로봇은 Modbus 대신 PROFINET · EtherNet/IP · CC-Link 같은 필드버스나 하드와이어 I/O 를 쓰는 경우가 많습니다. 이 에뮬레이터의 Modbus 는 **로직 개발용 대체 경로**이므로, 실제 장비에서는 같은 신호를 해당 필드버스의 I/O 맵에 옮겨야 합니다.

### 12.3 PC·HMI·SCADA 연동 — OPC UA

- 엔드포인트: `opc.tcp://<IP>:4840/UA/RobotEmulator`, 보안 None + 익명 (Basic256Sha256 도 가능, 클라이언트 인증서 자동 신뢰)
- 노드: `Objects/Robot/…` — 상태, 관절, TCP, IO, 레지스터, 제어 메서드(ServoOn, Start, MoveJoints 등)
- UaExpert 같은 범용 클라이언트로 먼저 탐색해 보는 것을 권합니다.
- 전체 노드 목록: [README › OPC UA 주소 공간](../README.md#opc-ua-주소-공간)

### 12.4 제조사 프로토콜

| 제조사 | 실제 사용처 | 에뮬레이터 접속 | 확인할 점 |
|---|---|---|---|
| **Yaskawa** HSE (UDP 10040/10041) | MotoCom 대체, PC 에서 상태·변수·잡 제어 | 헤더 `YERC` 32 바이트 패킷 | 명령 0x70~0x8B, 0x300~0x306. 부가 상태 코드는 실제 매뉴얼로 검증 필요 |
| **Kawasaki** AS 터미널 (TCP 23 / 10023) | KRterm, 텔넷 기반 명령 | `login:` 에 아무 사용자 → `>` 프롬프트 | WHERE, ZPOW, EXECUTE, HOLD/CONTINUE, LOAD/SAVE (Ctrl-Z 종료) |
| **Hyundai** Hi6 Open API 스타일 REST (8888) | 상위 PC REST 연동 | `/project/...` 근사 경로 + 에뮬레이터 표준 `/api/...` | **공식 사양 미검증.** 실제 경로·필드명은 현대로보틱스 매뉴얼로 확인 |
| **ABB** RWS 1.0/2.0 (8080) | PC SDK 대체, 웹 연동 | `Default User / robotics` 또는 인증 없음 | 실제 IRC5 는 80, OmniCore 는 443(HTTPS). 구독은 WebSocket |
| **KUKA** KukaVarProxy (7000) | OpenShowVar, Python `py_openshowvar` 등 | 바이너리 TCP | `$AXIS_ACT`, `$POS_ACT`, `$OUT[n]`, `.dat` 전역 변수 |

각 프로토콜 파일(`server/protocols/*.js`) 상단 주석에 지원 명령과 실제 컨트롤러와 다른 점이 정리되어 있습니다.

### 12.5 연동 시험 순서 (권장)

1. **로봇 측 확인**: 해당 제조사 로봇을 선택하고 예제 프로그램이 끝까지 도는지 확인.
2. **접속 확인**: 샘플 클라이언트로 상태 읽기.
3. **읽기 연동**: 자체 프로그램으로 상태·위치·I/O 를 읽고 화면 값과 비교.
4. **쓰기 연동**: DI 쓰기, 변수 쓰기 → 에뮬레이터 `I/O` 탭 · `변수` 탭에서 반영 확인.
5. **제어 연동**: 서보 ON, 시작, 홀드, 정지, 알람 리셋.
6. **시나리오 시험**: 로봇 프로그램과 PLC 로직을 함께 돌리며 신호 타임라인으로 핸드셰이크 확인.
7. **이상 상황**: 프로그램 실행 중 `■ 정지`, 간섭 알람 유발(간섭 체크 `정지` 모드에서 장애물로 이동), 통신 케이블 분리(에뮬레이터 종료) 등에 대한 PLC 측 처리를 확인.

## 15. 설정 파일 (config.json)

프로젝트 루트에 만듭니다. 지정하지 않은 항목은 기본값을 씁니다.

```json
{
  "httpPort": 3000,
  "host": null,
  "robot": "kuka-kr6-r900",
  "gripper": "robotiq-2f85",
  "restoreSession": true,
  "protocols": {
    "yaskawaHse":   { "port": 10040, "filePort": 10041 },
    "kawasakiAs":   { "port": 23, "fallbackPort": 10023 },
    "hyundai":      { "port": 8888 },
    "abbRws":       { "port": 8080 },
    "kukaVarProxy": { "port": 7000 },
    "modbus":       { "port": 502, "fallbackPort": 1502 },
    "opcua":        { "port": 4840 }
  },
  "ai": { "model": "claude-opus-5-5", "effort": "high" }
}
```

| 키 | 설명 |
|---|---|
| `httpPort` | 웹 UI·REST·WebSocket·MCP 포트 (환경변수 `PORT` 가 우선) |
| `host` | 바인딩 주소. `null` = 모든 인터페이스, `"127.0.0.1"` = 이 PC 만 (환경변수 `HOST` 가 우선). 통신 모듈에도 적용 |
| `robot`, `gripper` | 시작 시 로봇·그리퍼. `robot` 을 지정하면 자동 저장 복원을 하지 않음 |
| `restoreSession` | `false` 면 직전 세션 복원 안 함 |
| `protocols.<키>.enabled` | `false` 면 해당 인터페이스 끔 |
| `protocols.<키>.port` / `fallbackPort` | 포트 / 바인딩 실패 시 대체 포트 |
| `protocols.<키>.host` | 해당 인터페이스만 다른 바인딩 주소 |

## 16. 공용 REST / WebSocket API

자체 시험 자동화 스크립트에서 에뮬레이터를 직접 제어할 때 씁니다.

- `GET /api/state` — 전체 상태 스냅샷 (관절, TCP, I/O, 프로그램, 알람, 사이클, 배속 …)
- `GET /api/robots` — 로봇·그리퍼·제조사 목록
- `GET /api/comms` — 통신 인터페이스와 실제 포트
- `POST /api/cmd` — JSON `{ "cmd": "...", ... }`
- `ws://<host>:3000/ws` — 같은 명령을 `{ "cmd": "...", "id": 1 }` 로 보내면 `{ type: "reply", id: 1, ok }` 응답. 상태(`state`, 최대 30 Hz)·로그·타임라인 이벤트가 푸시됨

| cmd | 인자 | 동작 |
|---|---|---|
| `setRobot` | `id` | 로봇 변경 |
| `setGripper` | `id` | 그리퍼 변경 |
| `servo` | `on` | 서보 ON/OFF |
| `mode` | `mode` (TEACH/PLAY/REMOTE) | 모드 |
| `override` | `value` (1~100) | 오버라이드 |
| `timeScale` | `value` (0.1~10) | 배속 |
| `moveJoints` | `joints[6]`, `speed` (0~1) | 관절 이동 |
| `moveHome` | | 홈 이동 |
| `setDO` / `setDI` | `n`, `v` | I/O 쓰기 |
| `saveFile` / `deleteFile` / `setMain` | `name`, `text` | 프로그램 파일 |
| `start` / `step` / `hold` / `resume` / `stop` / `reset` | | 실행 제어 |
| `resetAlarms` / `resetScene` | | 알람 리셋 / 공작물 초기화 |
| `breakpoints` | `list` (`"파일:줄"`) | 브레이크포인트 |
| `vars` / `timeline` / `timelineClear` | | 변수 / 신호 타임라인 |
| `cell` | `op`, … | 셀 레이아웃 (`get`/`set`/`preset`/`resetObjects`/`add`/`remove`/`update`) |
| `projectSave` / `projectLoad` / `projectExport` / `projectImport` | `name` / `project` | 프로젝트 |
| `state` | | 상태 스냅샷 |

예 (PowerShell 에서는 `curl.exe`):

```bash
curl -X POST http://localhost:3000/api/cmd -H "Content-Type: application/json" -d '{"cmd":"setDI","n":5,"v":true}'
```

## 17. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| `HTTP 서버 시작 실패 … 포트가 이미 사용 중` | 다른 프로그램(또는 이미 실행 중인 에뮬레이터)이 3000 번 사용 중. `PORT=3100 npm start` |
| Kawasaki 가 10023, Modbus 가 1502 로 뜸 | Linux/macOS 에서 1024 미만 포트는 관리자 권한 필요 → 자동 대체. 원래 포트가 필요하면 관리자 권한 실행 또는 `sudo setcap 'cap_net_bind_service=+ep' "$(command -v node)"` |
| 통신 탭에 `(비활성)` | 포트 충돌. 로그의 `통신` 항목에서 원인 확인 후 `config.json` 에서 포트 변경 |
| 다른 PC·PLC 에서 접속 안 됨 | ① `HOST=127.0.0.1` 로 실행하지 않았는지 ② 방화벽 허용 ③ 같은 IP 대역 ④ `ping` 확인 |
| OPC UA 접속 시 인증서 경고 | 자체 서명 인증서. 클라이언트에서 서버 인증서를 신뢰. 인증서를 새로 만들려면 `.opcua-pki/` 삭제 후 재시작 |
| `시작` 해도 동작 안 함 | 로그 확인: `알람 리셋 후 시작하십시오` → 알람 리셋, `서보 OFF` → 서보 ON, 컴파일 오류 → 에디터 아래 메시지 |
| `목표 위치에 도달할 수 없습니다` 알람 | 작업 영역·관절 한계 밖. `작업 영역 표시`로 범위 확인 |
| 로봇이 테이블 앞에서 멈추고 `COLLISION` 알람 | 간섭 체크 `정지` 모드. `알람 리셋` 후 조그로 빠져나오거나 간섭 모드를 `경고`로 |
| 3D 화면이 검거나 느림 | 브라우저 하드웨어 가속(WebGL) 확인. 저사양 PC 는 `궤적 표시`·`작업 영역 표시` 끄기 |
| 서버 재시작 후 이전 상태가 아님 | `config.json` 에 `robot` 을 지정했거나 `restoreSession: false` |

## 18. 제한 사항 — 실제 로봇과 다른 점

PLC·PC 개발에 영향을 주는 순서로 정리했습니다.

1. **모드 인터록 없음**: 실제 컨트롤러는 REMOTE(외부 운전) 모드에서만 외부 시작을 받고, TEACH 모드에서는 거부합니다. 이 에뮬레이터는 모드와 관계없이 외부 명령을 받습니다. 모드 확인 로직은 PLC 쪽에서 상태 비트로 직접 검증하십시오.
2. **안전 신호 없음**: 비상정지, 안전 펜스, 인에이블 스위치, 외부 서보 ON 같은 하드와이어 안전 신호와 그에 따른 정지 범주(Stop 0/1/2)를 모사하지 않습니다.
3. **전용 시스템 I/O 없음**: 제조사별 전용 입출력(외부 시작·홀드·리셋, 프로그램 번호 선택, 운전 중·알람·원점 출력 등)이 고정 할당되어 있지 않습니다. 같은 동작은 Modbus 명령 레지스터나 범용 DI/DO 와 로봇 프로그램으로 구성해야 합니다.
4. **필드버스**: PROFINET · EtherNet/IP · EtherCAT · CC-Link 는 지원하지 않습니다 (Modbus TCP / OPC UA 로 대체).
5. **프로토콜 검증 수준**: 각 프로토콜은 공개 매뉴얼 기반이며 실제 컨트롤러와 바이트 단위로 대조하지 않은 부분이 있습니다. 특히 Hyundai Hi6 API 경로, Yaskawa HSE 부가 상태 코드.
6. **알람 코드**: 알람 번호·메시지는 실제 제조사 코드 체계와 다릅니다.
7. **로봇 치수·동특성**: 공개 카탈로그 기반 근사값. 가반하중에 따른 가감속, 브레이크 정지 거리 미반영. 사이클 타임은 참고값.
8. **통신 타이밍**: 응답은 거의 즉시 옵니다. 실제 컨트롤러의 응답 지연·처리 주기·동시 접속 제한은 모사하지 않습니다.
9. **간섭 체크**: 캡슐 근사로 실제 외형과 수 mm ~ 수십 mm 차이.
10. **보안**: 인증 없음.

개선 계획은 [ROADMAP-SI.md](ROADMAP-SI.md) 를 참고하십시오.
